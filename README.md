# QCL · Quanta Craft Launcher

> **目前手机启动器唯一支持下载所有考古社区已归档远古版本的；也是唯一给「全远古版本」做好中文的启动器。**

**Quanta Craft Launcher (QCL, 量子方块启动器)** is an Android launcher for Minecraft: Java Edition.
Since 1.1.1 the launch / render / input / Java-runtime pipeline is **self-built**, with
[FoldCraftLauncher (FCL)](https://github.com/FCL-Team/FoldCraftLauncher) as the reference;
versions 1.1.0 and earlier were based on [HMCL-PE](https://github.com/Tungs-HMCL/HMCL-PE).
Maintainer: **Rod123456** (bilibili UID 550905358).

**English summary:** QCL focuses on *ancient* Minecraft versions (pre-classic / classic / indev / infdev /
alpha / beta / RC) — **the only Android launcher that currently supports downloading every *archived* ancient
version** (258 archived builds; builds the community never archived are not downloadable) — and the only one that ships Chinese patches for **all** ancient versions. Each archived build
is installed with its dependencies and assets fetched automatically. It also supports modern
versions up to 26.x (Java 25). Pojav launch backend with native SDL3 windowing,
automatic 32/64-bit runtime detection, dynamic memory clamping, a launch-log overlay, a crash screen, and
multiplayer powered by Terracotta (China mainland only). Licensed under **GNU GPL-3.0** — see
[`LICENSE`](LICENSE) and [`THIRD_PARTY_NOTICES.md`](THIRD_PARTY_NOTICES.md).

## 这是什么

QCL 是一个安卓平台的 Minecraft Java 版启动器，界面按自己的「QCL 灰色半透明」风格重做，重点解决
**远古版本（pre-classic / classic / indev / infdev / alpha / beta / RC）能不能装、能不能启动**的问题，
同时支持到最新的 26.x（2026 年官方改历年命名）。

## 主要特性

### 启动链路
- **32/64 位运行时自动检测**：跟随设备与应用实际 ABI 自动选择（可在设置里手动强制）
- **内存安全**：按运行时位数给默认值（64 位 2GB / 32 位 1GB），并按**当前剩余内存**动态夹取，避免 VM 初始化失败把启动器一起带走
- **启动后端**：Pojav（1.1.1 起原生 SDL3 图形窗口，支持 26.3+）。
  ⚠️ **Boat 后端已移除** —— 1.1.x 起源码、资源、manifest 声明都已删除，启动器里也没有切换入口了。
- **长按启动键**可切换渲染器（Krypton Wrapper / Holy-GL4ES / Zink / VirGL / Freedreno / VGPU / MobileGlues；默认 Krypton，全版本通吃）
- **启动日志悬浮窗**：默认开启，实时显示 JVM 与游戏输出，进入游戏主界面自动关闭（可在游戏内悬浮窗开关）

### 渲染器
QCL 自己写的是**窗口 / Surface / EGL 上下文 / 输入桥 / 帧节奏**这一层；
真正把 OpenGL 调用翻译成设备 GLES 的**渲染器本身，目前全部是第三方库**（长按启动键切换）：

| 名称 | 库 | 说明 |
|---|---|---|
| **Krypton Wrapper**（默认） | `libng_gl4es.so` | OpenGL 3.1+，全版本通吃；官方支持到 26.3-snapshot-3 |
| **Holy-GL4ES** | `libgl4es_114.so` | OpenGL 2.1，老版本更稳 |
| **Zink** | `libglxshim.so` | OpenGL 4.6（Mesa zink on Vulkan），支持到 26.3-snapshot-3 |
| **VirGL** | `libOSMesa_81.so` | 软渲染（VirGLRenderer） |
| **Freedreno** | `libOSMesa_8.so` | OpenGL 4.6，仅高通 adreno616-a660 |
| **VGPU** | `libvgpu.so` | OpenGL 2.1+ |
| **MobileGlues**（已内置） | `libmobileglues.so` | 随 APK 打包（约 7.8 MB，含四 ABI），选中即可用、无需另装插件 APK；26.3+ 由 QCL 自动追加 `--graphicsBackend vulkan` |

**自研渲染器（进行中）**
- QCL 计划**自研一个自己的渲染器**，并**明确不以 MobileGlues 为模仿对象、不复制其实现思路**。
- 起因（如实记录）：我们此前向 `MobileGL-Dev/MobileGlues` 提交过 PR（#59，26.3 崩溃的空指针保护），
  被维护者驳回并要求「修根因、别再提补丁式 PR」，随后该问题由官方自行处理。
  由此我们决定**不再向该仓库提交任何东西**，兼容性只做到「**能识别、能加载它**」，
  一切以其自身实现为参照，QCL 走自己的路。
- **进度：尚未发布，因此渲染器列表里暂时没有这一项** —— 不做装上却不能用的假选项。
- **自研渲染器的第一件事：把这个颜色链路做对。** 远古版本（Classic 等）目前会出现天空/场景被大块
  红紫青色块覆盖的现象，成因在**第三方渲染器这一层** —— gl4es / Zink 这类 GL→GLES 转译器
  **共用同一套颜色处理链路**，问题出在**首帧图形状态建立之后被固化**（窗口/表面建立 + 首次着色器编译那一段）。
  对同一份 jar 换任何一款第三方渲染器结果都一样，**FCL 等同样基于 gl4es 的启动器也一样** ——
  这是**所有走第三方转译路线的安卓启动器共有的天花板**，不是 QCL 自身的缺陷。
  自研渲染器落地后，QCL 将成为**唯一一个在远古版本上颜色完全正确的安卓启动器** ——
  这比"支持下载全部归档版"更硬，因为那是别人做不到，而不是没做。

### 当前进展（1.5.2）

### 当前进展（1.5.8）

- **Minecraft 26.3 终于能启动了**（从 1.5.1 挂到 1.5.7 都没定位）—— 真根因是
  **「官方默认值 + 渲染器」的组合**，**不是 QCL 的 bug**：
  - 26.2 引入了 Vulkan 后端，但 **26.3 的默认图形 API 仍是 `DEFAULT`（= OpenGL）**；
  - 走 OpenGL 时这条 GL 路径会经过 `libmobileglues.so` 的 `glGetString`，它在部分查询上返回 `NULL`；
  - 调用方对 `NULL` 取 `strlen` ⇒ **原生 SIGSEGV**（空指针解引用），表现为黑屏崩溃。
    tombstone 铁证：`__strlen_aarch64 ← glGetString ← libmobileglues.so`。
  - **26.4 官方把 `Default` 改成等同 `Prefer Vulkan`**，所以同一台手机、同一份 MG 下 26.4 一直能进 ——
    这就是「崩 26.3、不崩 26.4」的全部原因。
  - 修法：从 26.3 起启动时追加**官方支持的启动参数** `--graphicsBackend vulkan`。
    为什么不写 `options.txt`：① 写根目录无效（QCL 默认各版本独立）；② 写 `versions/<ver>/options.txt`
    会被 26.3 在**上次异常关闭后主动重置**（`Detected unexpected shutdown... resetting preferred graphics API
    to Default`）；③ 写进 `onCreate`/`onSurfaceTextureAvailable` 也不行 —— 26.3 走 SDL3，该回调根本不触发。
    启动参数优先级高于游戏内设置、且不受异常关闭重置影响。**26.2 及以下一律不碰**（那些没有 Vulkan 后端）。
- **MobileGlues 已内置**（`QCL/libs/MobileGlues-release.aar`，7.8 MB，含四 ABI 的 `libmobileglues.so`）——
  以前要让 MG 生效得自己装 MG 的插件 APK，现在随启动器打包，选中即可用。
  库解析顺序：**内置（APK 自带）→ 外部插件 APK → `renderer/<id>/` 手放目录**。
- **自动写 MG 配置**（`<files>/mobileglues/config.json`，`enableNoError=2`）——
  键名这里踩过坑：MG 读的是 `enableNoError`（源码 `settings.cpp`），**不是** `ignoreError`；
  日志里那句 `[MobileGlues] Setting: ignoreError = 0` 是内部枚举值（0=None），不是配置键。
  `enableNoError=0` 时不吞 GL 错误 ⇒ `GL_UNIFORM_BUFFER_OFFSET_ALIGNMENT` 取不到 ⇒
  `minUniformOffsetAlignment()` 返回 0 ⇒ `Mth.positiveCeilDiv` 除零 ⇒ `DynamicGpuDataStorageMapped.<init>`
  抛 `ArithmeticException`（这是**另一个**独立的崩溃，和上面的 SIGSEGV 不是一回事）。
  `MG_DIR_PATH` 指向该目录还顺带让 MG 的「不支持的启动器」分支恒假，**因此不需要伪造 `FCL_VERSION_CODE`**。
- **首次进世界转视角「大片移一下」** —— `CallbackBridge.sendCursorPos` 加了 `NaN` 哨兵，
  抓取态变化时重置光标增量基准（原来首帧把**绝对坐标**当成了增量）。
- **新增「查看上次启动日志」**（左侧栏第 7 个按钮）—— 尾部 2000 行、等宽 10sp、明暗自适应；
  用于游戏在等待界面就崩、连崩溃弹窗都弹不出来时导出日志。
- **日志不再过滤掉原生崩溃** —— `logcat` 白名单原来只有 `jrelog`/`LIBGL`，
  JVM 原生崩溃打的 `F/DEBUG`（tombstone）、`F/libc`、`E/AndroidRuntime`、`A/art` 全被 `-s` 滤掉，
  日志在 `-cp` 之后直接断掉；现已补上这些 tag，并把 `-v brief` 换成 `threadtime`。
- **26.4 快照的 JNA 5.19.1 崩溃**（`NoClassDefFoundError: NativeLong`）—— 新增 `JnaNatives`，
  从 `assets/app_runtime/jna/<ver>/natives/<abi>/` 解压，缺失时从 aliyun / 华为云 / repo1 下载 aar 抽取。
- **安装器（Forge / NeoForge / Cleanroom）JVM 起不来时不再卡住** —— `catch Throwable` 返回 255，
  并在日志里明确标注「安装器/JVM 启动失败」。
- **26.3+ 写 `config/fml.toml` 的 `earlyWindowControl=false`**（避免 FML 抢先建窗口）；低版本则删除该键、绝不残留。
- **自定义背景图改 `inJustDecodeBounds` 采样解码**，切换前回收旧 bitmap，解码失败回落
  `ic_background_classic` 而不是崩。
- **公告不再折叠** —— 1.5.7 曾把正文限成 6 行，结果「大部分内容看不见」，已撤销：
  `setMaxLines(Integer.MAX_VALUE)` + `setEllipsize(null)`，内容放不下就滚动，不截断。

### 当前进展（1.5.7）

- **Legacy Fabric / Legacy Fabric API 加版本限制** —— 这两个加载器只支持 MC **1.3 – 1.13.2**
  （外加部分快照版本与愚人节版本）。以前对任何游戏版本都照常显示这两行，玩家选了个 1.20.1

  Modrinth 的 `legacy-fabric-api` **168 个**（两者上限不同 —— 前者到 1.13.2、后者只到 1.12.2，
  所以分开建表不共用）。不支持的版本**整行隐藏**（不是把文字改成"不支持"还留着箭头），
  把游戏版本切到不支持的范围时会顺手清掉之前选的非法 Legacy 版本；给已有实例补装加载器、
  以及点进列表之前都加了二次校验，不支持就直接弹出支持范围，不再让人对着空白页发呆。
- **修好「收藏页取消收藏，大退重进又复活」** —— 删除逻辑一直是对的，
  **是写盘被自己的「防丢数据」守卫拦住了**：`save()` 里那条
  「内存列表为空 && 文件非空 ⇒ `return` 不写盘」，恰好会在玩家把收藏取消到一条不剩时成立，
  于是磁盘文件保持旧内容、重启后全部复活（这也解释了 2026-10-16 那次「双键匹配」修复为什么没救回来）。
  现在只在「从未成功读取过收藏文件」时才拒绝写入，空列表属于玩家真实意图、必须落盘；
  防丢数据改由「加载失败拒写 + 原子写并保留 `.bak` + 写后回读校验」三件事承担。
  另外收藏页那个 ★ 取消收藏改成按 `id` → `source:slug` → `source:modId` **三路兜底**删除
  （历史数据里 `id` 与 `source:modId` 脱节时，原来一条都删不掉却照样刷新界面 —— 看着删了、重启又回来），
  删不掉会明确提示，不再假装成功。

### 已知问题（如实列出）
> 这里只放**当前版本仍未解决**的项，并且分清楚是哪种"没解决"：
> **QCL 还没做到**（我们自己的活，有明确路线）与**这类方案都做不到**（横向对比过的天花板）。
> 已修的问题不在此列 —— 各版改了什么见 Release 说明，README 不逐版记录。

- **点两次 ESC，视角偶发偏移（时好时坏）** —— 属于 **QCL 这边还没查清的缺陷**，不是行业问题：
  以前怀疑的成因经复核不成立，贸然改会引入新毛病，需要一次**可复现的日志**才能定位。
  1.4.3 修掉的三处视角问题（关菜单猛偏、进游戏第一次滑动大偏、抓取状态延迟 250 毫秒）不受影响。
- **远古版本（Classic 等）颜色异常** —— 属于**第三方转译路线共有的天花板**，不是 QCL 自身的缺陷：
  成因在第三方渲染器那一层（gl4es / Zink 共用同一套颜色处理链路，问题出在首帧图形状态被固化），
  换任何一款第三方渲染器结果都一样，**FCL 等同样基于 gl4es 的启动器也一样**。
  彻底解决取决于**自研渲染器**，它的第一件事就是把这个颜色链路做对（详见上文「渲染器」一节）。
- **投影工坊的 `.litematic` 导出** —— **有意暂不做**：这种格式的 NBT 结构复杂，现在导出无法保证正确，
  宁可只提示也不生成一个损坏的投影文件（`.schematic` 导出可正常使用，但属旧格式：
  256 高、不带方块状态）。
- **整合包导入的格式覆盖** —— 目前**真正接通的是 MultiMC / Prism**（导入时会自动补下游戏本体、
  处理 jarmods / patch）；CurseForge / Modrinth(`.mrpack`) / MCBBS / 服务器整合包
  **还在补齐中**（这些提供器能识别清单，但安装任务还没接通）；
  FCL 那套实现深度绑定它自己的框架，不能直接搬，得按 QCL 的架构重写。

**西文字符被画成乱字形**，并与标签重叠；纯中文按钮与纯英文界面一直正常。

**根因**：中文补丁的字体渲染器把「中文字形」与「西文字形」放在两张纹理上。绘制时西文字符
先攒进队列、遇到中文字符才真正送显；而中文字符的显示列表内部会绑定自己的点阵纹理。
于是排在中文后面的西文字符（比如「音乐: 关」的冒号）在**错误的纹理**上取字形 → 乱码。

**修复**：每次把西文队列送显前重新绑定西文字体纹理。涉及全部 9 个补丁字体类
（b1.6 系 `se`、b1.7.3 系 `sj`、b1.8 系 `kh`、1.0 `abe`、b1.9 全系 `lf/ls/mc/mb/mf`）。
期间曾因字节码插入顺序错误导致 b1.7.3 启动 VerifyError，已修正并实机复测。

**附带**：补丁标记（`.cnpack_lang`）加上启动器 versionCode —— **启动器升级后自动为
已安装的远古版本重新注入最新补丁**，不再需要删除版本重装。

**已验证**：b1.9-pre5 选项界面（音乐: 100% / 音效: 100% / 鼠标反转: 关 / 灵敏度: 100% /
视场角: 极小 / 难度: 普通）与 b1.7.3 选项界面全部正常；1.20.6 高版本回归无影响。

**本版修掉的问题** ✓

1. **启动崩溃 `NoClassDefFoundError: co`** —— 注入时 `isPatchedEntry` 漏排除 b1.9/b1.6 分支，把游戏自己的原生类当补丁类删掉了。
2. **中文一个字都不显示** —— 高度算法 `fh = (gw >>> 4) - 1` 在中文（`glyph_sizes` 值为 `0x0F`）时算出 **-1**，字形退化成 1 像素横条。
3. **每个字右边多一条竖线** —— 绘制宽度用了整整一格（16px），采到了隔壁格的像素（原版用 `7.99` 就是防这个）。
4. **字大得离谱、挤成一团** —— 原版字体纹理是 128×128、每格 8×8，中文点阵是 256×256、每格 16×16，**必须缩一半**画成 8×8。
5. **改小后只剩偏旁** —— UV 跟着屏幕尺寸一起减半了。**UV 跨度要恒取整格 16，只有屏幕跨度才是 7.99**。
6. **「选项」按钮旁出现乱字符** —— `menu.options=选项...` 的 3 个 ASCII 句点落在原版纹理的空白格上，采到错误像素。已改为中文省略号（走 CJK 字形页）。
7. **FOV 选项显示成 `options.fov` 键名** —— 语言文件缺 `options.fov` / `options.fov.min`，已补（视场角 / 极小）。

**1.3.5 已修复上面遗留的「值部分重叠」**：根因是中英混排时西文字符在中文点阵纹理上取字形（详见下方 1.3.5 段）。

## 构建

```bash
export JAVA_HOME=/path/to/jdk-17
./gradlew :QCL:assembleRelease
# 产物：QCL/build/outputs/apk/release/QCL-release.apk
```

- 环境：Gradle 7.3.3 / JDK 17 / NDK 27.3.13750724 / compileSdk 34 / minSdk 26
- 签名：请**自备** keystore（仓库不包含签名密钥），在 `QCL/build.gradle` 中配置

### 运行库（已内置）
`QCL/src/main/assets/app_runtime/java/` 已包含全部常用 Java 运行时，**克隆仓库即可完整构建，不需要再从任何 Release 附件补包**。

每个运行时目录里都是与 FCL 同款的架构分卷（`bin-<架构>.tar.xz` + `universal.tar.xz` + `version`）：

| 仓库目录 | Java 运行时 | 架构分卷 | 目录体积 | 设备端解压到 |
|---|---|---|---|---|
| `jre8/` | Java 8 | arm / arm64 / x86 / x86_64 + universal | 27.3 MB | `default` |
| `jre17/` | Java 17 | arm / arm64 / x86 / x86_64 + universal | 38.3 MB | `JRE17` |
| `jre21/` | Java 21 | arm / arm64 / x86 / x86_64 + universal | 46.3 MB | `JRE21` |
| `jre25/` | Java 25 | arm / arm64 / x86_64 + universal（**无 x86**） | 49.0 MB | `JRE25` |

- 四个运行时的内容与 FCL 的 `FCL/src/main/jreAssets/app_runtime/java/` **逐字节一致**（23 个文件中 22 个 md5 完全相同；唯一差异是 `jre8/version` 的版本计数 `13` → `14`，QCL 用它触发设备端重新解压）。
- **单文件最大 32.8 MB**（`jre25/universal.tar.xz`），远低于 GitHub 单文件 100 MB 硬上限，所以 **23 个文件全部已入库**。
- 早先那个 121 MB 的 `lib/modules` 单文件已不存在 —— 它现在被压缩进 `universal.tar.xz`（32.8 MB）。**`JRE25-runtime.zip` 附件已作废，不需要了。**
- Java 25 没有 x86 分卷（上游未提供）；在 x86 设备上安装器会直接跳过 Java 25。
